# 接手、迭代与验收清单

## 接手顺序

1. 阅读根 README 的版本映射、归档差异及许可边界；先选一个工程，不从三个工程拼出未经验证的新版本。
2. 用 `.nvmrc` 版本安装依赖，校验素材哈希；检查本轮 `verification.md` 的通过、失败和未执行项。
3. 构建后仅在独立端口启动，确认页面、`public/build-info.json`、素材及只读 API 能返回；在隔离本地数据库中验证加入/离开/断线/重连和容量。
4. 做一次两客户端行为验收：A 的有效操作改变 B 的共享状态；刷新不伪造持久化，断网有真实反馈，NPC 与真人分开计数。
5. 新玩法先写一个核心行为循环及边界，再实现最小灰盒；详细顺序见开发指引。

## 发布前必须明确

- 本轮验证的是哪个 commit、哪组资产哈希、哪个数据库 schema；构建成功与视觉验收分别记录。
- 本地模拟、实时联机、持久化、浏览器本地缓存分别由什么代码负责；不能把 `localStorage` 称为跨设备云存档。
- 只向新建或明确授权的站点配置生产身份；归档已移除原站点 `project_id`。不能照抄其他应用 ID 或把旧线上站点当测试环境。
- `dist/server/wrangler.json` 是生成产物；迁移到独立 Cloudflare 环境需配置自己的 D1 及相应平台权限。Sites 的身份/连接器能力也需要相应宿主，代码备份不会自动复制这些平台服务。
- 原始数据库、会话 Cookie、令牌、`.env*`、账号信息、私有输入素材和聊天记录不得写入仓库或压缩包。
- 资产 unknown 权利项是否已获得目标分发范围所需确认；不能用“此前在线”替代许可。

## 可复现的验收记录

记录环境版本、命令、退出码、用时、目标 URL/端口、响应摘要；失败写成失败。保存源码与资产清单，不上传实际玩家记录。低成本检查先跑，密集网格测试受限并发并在后台/云端执行。

本轮按用户要求不操作本机浏览器和桌面。UI/手机触摸、首帧、模型观感、音频自动播放、长时间运行、双真实客户端和真机 FPS 均需接手者在获准环境补验，不能用单元测试代替。

## 版本备份与仓库上传

- `python3 scripts/package.py` 生成可重复源码包，`artifacts/packages.json` 给出包哈希。
- 使用清晰归档分支；有默认分支时从其最新提交建立分支，把本交付目录合并进去，保留无关文件。
- 先核对仓库 visibility、当前登录账号、write 权限和分支规则；403/404 需解决访问授权，不能另建同名仓库、改公开或 force push。
- 上传完成的证据是远端 commit 与可读文件，不是本地 commit。远端存在默认分支时可创建 draft PR供审阅；无提交空仓库需要按其实际初始状态处理。
- 发布 Demo 是单独动作。本归档任务不修改线上三个站点，也不把新迭代混进本次旧版基线。
