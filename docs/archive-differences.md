# 与准确发布基线的差异

发布基线分别为云蹦迪 `b957db28…`、云钓鱼 `55de7c92…`、火人节 `1237c681…`。来源核验记录见 [版本映射](../manifests/versions.json)。恢复仓库HEAD与保存发布commit一致，未使用文件修改日期、较早下载包或小岛v0.2源码推断最终版。

为满足本次仓库交付边界，仅在归档副本进行了以下处理：

1. 不复制 `.git` 历史、安装依赖、dist、环境变量、运行数据库和宿主状态。
2. 不直接复制旧 `docs/`、README与RESTORE原文；此次重新编写开发指引、设计原则、工程README及交接报告。`scripts/` 下与资产重建有关的说明、第三方LICENSE和公开署名保留。
3. 删除每工程9张来源与公开授权不明的个人主页图片；替换所有相关代码/既有测试路径为同工程中性SVG。示例主页固定姓名与图片替代文字改成中性说明。没有重设计游戏场景。
4. 从 `.openai/hosting.json` 移除生产 `project_id`，保留 `d1`/`r2` 运行声明，防止接手者误发到旧站点。新的目标需要重新明确配置。
5. 新增 `.nvmrc`，记录本轮使用的 Node 24.9.0；依赖版本及 package-lock 未升级。
6. 新增 `scripts/init-local-db.mjs` 和 `npm run db:init`。原生成配置的默认迁移目录不指向 `drizzle/`，新脚本在ignored运行目录生成仅本地迁移配置并强制 `--local`，让全新工程从零运行共享状态API。
7. 新增归档打包、资产验证脚本及全新交接文档、清单；ZIP包不进入Git。

火人节原生产Site身份测试同步改为验证归档不携带生产身份，其余版本与入口约束保留；没有删除旧玩法测试。

完整逐文件状态与新增路径见 [archive-adjustments.json](../manifests/archive-adjustments.json)。旧来源保留在隔离恢复目录中；本次仓库分支不带原项目历史，避免把无关资料和历史资产重新带入。

因此这是一份“准确线上源码基线 + 明确脱敏和本地恢复调整”的归档，不是声称与线上字节完全相同的镜像。核心玩法没有进行新功能迭代，最新小岛经验仅可能作为标注清楚的设计建议出现。
