# 可玩性修复与后续完成顺序

本轮范围是 V5.2.1：先让现有游戏从开场到行走、照料和复访形成可靠闭环。保持原 390×844 Feed、固定斜俯视镜头、LX 与当前存档；不合入尚未验证的 V5.3 扩展。

## 本轮确切修复

1. 旧存档已经完成狼退场，却仍停在教学门禁：进入后自动完成一次安全握手，解除遮罩与移动锁，不强行打开卡片。
2. 进入会话过程中点击使用旧会话：队列在真正发送时绑定当前会话；结果不确定的重试仍保留原请求 ID 和完整内容。
3. 羊、狼和守护者每次重算路线回到取整点：共同导航保留分数位置、实际转角和施工碰撞节点。
4. 低频快照被高速追赶、整条开场路线回放过去路段、界面更新倒拨时钟：连续时间轨迹只沿已授权路线渲染；平滑转身，脚步取决于走过的距离；进出棚经过开门位置。
5. 卡片与动作流程：刷新恢复正在喂的对象；切动作目标保留动作抽屉；切演示档关闭旧设置；首次连接失败重试建立会话；拒绝原因显示在场景内。

## 建议按这条路线体验

- 刷新现有地址。已经结束开场的老存档进入自由活动；新存档或设置里的独立回放才播放开场。
- 点空地行走，用摇杆/WASD 转向；点羊本体或名字打开各自卡片。拖摇杆不应误选动物。
- 点喂奶：LX 自动走近，再执行三秒喂养。中途换目标或走开可取消；食物与成长记录只结算一次。
- 打开动作菜单，切换三只羊比较回应；随后去草场、工作台和池岸。羊仍不下水。
- 使用官方主题预览/应用/撤回、已有设施布局和无损守护演练；刷新确认身份、动物关系与习惯保留。

## 验收边界

- 已有自动回归覆盖真实控制器、React 命令流程、Three 射线/相机/真实羊网格点选、逐帧位置与足迹、保存幂等及隔离生产入口。
- 数值与 Node DOM 检查不能证明 Chrome 里的视觉效果。当前无独立 Chrome 插件控制入口，WebGL 画面、触屏遮挡和实际帧率仍待真机验收。没有使用 CUA、Playwright 或其他浏览器绕行。
- 完整命令结果与构建记录以 VERIFICATION.md、verification/v521.json 为准；旧测试通过记录不代表这轮修复已覆盖所有体验问题。

## 接下来如何完成

按优先级推进，每一项先完成可见流程，再扩展：

1. **真机验收现有核心**：同一存档走完以上流程，确认点击命中、转弯、进出棚、三种角色步态、开场与回放。失败先修，不以增加测试数量替代。
2. **在线自然事件**：安心模式的在线调度、可见预警、频率上限、后台暂停与保存恢复；不补算离线袭击。
3. **有限托管**：显式开启、库存预算、实际路线与幂等；只照顾需求，不替玩家增加亲密或个人成长经历。
4. **幼鸭与水域**：明确程序化占位、真实物种/食物/阶段、岸坡浅水导航与动画；羊和鸭的路线限制分开。
5. **内容与社交**：现有本地主题、作品和访客演示继续明确标注。真实 AI、账号、好友/权限后端需要独立服务集成和验收，不用本地模板伪装。多人、自由3D、公开分享不在当前本机交付范围。

上述2–4仍是未集成工作，隔离检查点保留在 .local/checkpoints/，不能称本轮已实现。完整玩法基线见 GAMEPLAY.md，V5蓝图正文见 docs/V5-reference.md，外部服务边界见 V5_INTEGRATION.md。
