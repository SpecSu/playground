## 1. 理念与当前体验
用“种下想法、等待惊喜、去别人家发现创意、带回种子继续传播”代替固定图鉴收集。金币负责经营，水晶负责新创作额度；已形成的物种种子可复用，不需要每次重新生成。当前是验证体验的离线 MVP，不是生产级游戏后台。

固定 2.5D 视角，Canvas2D 场景与透明 2D 美术，手机优先。底部为「种植 / 建造 / 串门」。四格起步、成长、收获、售卖、永久建筑图纸、地块扩展/配色、边缘篱笆矮墙、个人换装、四位好友、种子领取/传播署名均保留。

- 自家六款个人建筑：完整毛绒猫咪、黄色 LAMY 钢笔、贴地悬浮汽车、富士相机、扇贝屋、露营天幕。项链退出新建入口但历史实例仍兼容。
- 猫屋保留喂鱼与表情；汽车保留升降；主角苏贝壳保留圣诞装。建筑移位 20 金币，拆除 50 金币，不进背包；成熟植物可收纳/出售，成长中的不能新收纳。
- Kelly：恢复温暖音乐花园，保留键盘、鼓与留声机；Bear：潮玩与毛绒；吉吉：红黑哥特与玫瑰；LX：现代科技与整齐芦荟。低矮植物补足种植地，保留步道及互动位置。
- 点击植物、建筑或好友，人物走到可达的外侧位置并朝向对象。建筑占地不能行走。无实质操作 10 秒后闲逛，浏览菜单/移动视角不打断计时；主动操作优先。
- 演示快捷操作：双击金币 +100；双击成长倒计时让对应植物立即成熟。它们不是正式经济设计。

## 2. 必须理解的真实 / 模拟边界
| 能力 | 当前实现 |
|---|---|
| 创造 / remix | 有限的预制案例与关键词匹配，无实时生成 API；水晶由本地规则扣除 |
| 添加照片 | 仅当前输入草稿的本地缩略预览，可替换/删除；不上传、不存入存档、不驱动实际生成 |
| 邀请好友 | 原站固定安全链接的分享/复制界面；无邀请令牌、权限 ACL、账号或多人同步 |
| 好友家、排行、赠送 | 预制 NPC、mock 收益和本地赠送记录；没有真正通知或扣减他人账户 |
| 合影 | 四张预先绘制的自拍图，非游戏截图、非实时生图；当前角色装扮不会重绘照片 |
| 合影日期 | 打开时固定北京时间日期，显示在 UI 并写入下载文件名；原 PNG 像素本身没有新压日期 |
| 存档、交易 | 浏览器 localStorage，无服务端经济、防作弊或云同步；清理站点数据会丢进度 |
| 音频 | 无背景 MIDI/BGM；保留互动与金币音效，受用户手势、静音和后台暂停控制 |

## 3. 本地运行与验证
需要 Node.js 22+ 和 Python 3。无 npm 依赖，不需要 `npm install` 或任何 API 密钥。

```sh
cd inspiration-garden-2026-10-27
npm test
npm run check
npm run build
python3 -m http.server 4173 --directory dist
# 浏览器打开 http://localhost:4173
```

也可 `npm run serve` 从源码根目录启动。不要双击 index.html 使用 file://。如部署在子路径，请自行确认静态资源路径和邀请链接仍符合目标。邀请链接目前有意固定为原体验站点，不会自动指向新部署。

`npm run build` 会先从 `assets/garden-compositions.json` 同步 `src/gardens-data.js`，然后校验素材并按白名单构建 dist。修改布局请改 JSON 源，不要只改生成文件。详见 `VALIDATION.md`；本包复测结果与历史验收分开记录。

## 4. 目录导航
- `src/`：浏览器 ES 模块。`state.js` 原子交易；`storage.js` 校验/迁移/恢复；`catalogue.js` 物种与经济；`blueprints.js` 建筑规则；`scene.js` 渲染；`visual-walk.js` 行走；`ui.js`/`app.js` 入口界面。
- `src/footprints.js` / `construction.js`：占地、建造与完成时间；`edge-placement.js`：篱笆矮墙预览；`cloud-travel.js`：穿梭转场。
- `src/photo-sample-view.js`：固定合照加载下载；其余头像、照片草稿、邀请、互动、音频模块按文件名分层。
- `assets/`：完整已跟踪美术、音效、manifest、布局及来源卡；保留测试/兼容需要的历史素材。真正上线素材由构建白名单选择，不能仅凭文件名删除旧资源。
- `scripts/`：便携式检查与构建；`tests/`：Node 内置测试及固定 fixtures，无真实玩家存档。
- `docs/`：历史设计规格、实施计划、声音来源。部分历史方案已经撤回或被后续版本替代，不当作当前产品要求。
- `README.md` / `art-direction.md`：保留原工程阶段性说明，以此交接文件和当前代码为准。
- `dist/`：本次从完整源码重新生成的可运行静态产物；可删除后重新 build。
- `MANIFEST.sha256`：目录内文件校验清单（不含清单自身）。

## 5. 美术修改、性能和空间规范
保持统一固定等轴/斜视透视、暖色细轮廓、简单低频细节、柔和色块。不要再把复杂解构曲面、写实照片或高细节 3D 渲染直接混入。猫的完整形态具有纪念意义，不能被抽象掉；黄色钢笔保持简约直立形体与线圈笔夹。

素材入口由 manifests 控制。`art-manifest.json` 的图片相对路径、frame 源矩形、anchor 归一化锚点、width 显示宽度必须一起核对。透明底有效轮廓、落地点、遮挡排序和实际 footprint 要一致；新建筑可用 1×1、2×1、2×2，不能全部画成塞满四格的大方块。不要用视觉图层代替碰撞规则。

优先压缩 alpha WebP；保留需要的 atlas 和可编辑栅格源。生成图不是分层 PSD/3D 原文件，本仓库没有的生成工程不作承诺。裁切后重查 alpha 边界、动画留白/帧间隔、缩略图与地图上的实际显示；不要只看独立原图。合影按需加载，猫动画不要因 manifest 尚未就绪缓存空路径为永久失败。大图/icon 都要按实际显示尺寸压缩。

## 6. 存档与回归约束
存档命名空间 `inspiration-garden:v1`，与旧钓鱼庄园隔离。原始存档先做校验再 hydrate/default，不要改坏 checksum 或绕过 expected-head。保留已发布物种/图纸 ID、作者及衍生关系；新增免费图纸授予必须幂等、不重复收费、不强行放置建筑。历史种植 readyAt、旧项链实例、旧图纸来源须保留。

跨标签写入依赖 Web Locks 与预期版本校验；不可用时安全降级为临时游玩。坏档不得静默覆盖。测试清档前先备份，勿把用户真实 localStorage 导出提交。无服务端时不要宣称防刷金币/时钟作弊安全。
