# ENCORE · 分身舞者

私密、内部体验用的竖屏 3D 换装节奏游戏原型。桌面同样保持 9:16。

## 启动

```sh
npm ci
npm run dev -- --host 0.0.0.0
```

`npm test` 运行节奏判定、音频、连续舞蹈状态、七套真实骨骼、落脚/镜头范围、舞台缓存和资源档位测试；`npm run build` 输出静态 `dist/`。最终站点仅部署 dist，不部署工作目录或参考照片。

## 操作

1. 选择吉吉或 LX，再选择三套造型之一；也可打开“我的分身”面板，手动点一次“创建分身”，使用黑衣白裤基础造型。定制面板预填法老造型提示词，手动生成“埃及法老”后可穿着跳舞；实际模型就绪才解锁并扣除 100 本地积分。造型载入后登场。
2. 上下左右方向键 / WASD / 屏幕四个触控键，在符号抵达判定线时输入。
3. 暂停、继续；曲终查看今日好友模拟排名，或换装再玩。
4. 大厅内可在角色区域用鼠标或手指左右拖动查看，松手保留角度；上下滑动与界面按钮不参与转身。“看细节”用于近看造型；开始演出恢复正面全身镜头。
5. 可导入本地音频练习。文件只在浏览器内解码，不上传。自动 BPM 为估测，非人工谱面。

### 跳舞反馈

正确的节奏输入维持连续、灵活的整段舞蹈，包含转身与全身动作；不再按每个方向键切换一个简短姿势。Perfect / Good 会延续当前舞步，双押不重启动作。偶尔失误只短暂降低劲头；连续漏拍或停止输入会平滑回到休息姿势，重新跟上节奏后继续舞蹈。第一次有效命中前不会自动跳舞，暂停冻结动作与衰减计时。箭头判定、分数和连击仍由独立节奏系统计算。大厅自然摇晃、摆手招呼与换装转圈保留。

实现与验证见 [input-driven-motion.md](docs/input-driven-motion.md)；可复现的带材质离线动作视频流程见 [flow-motion-proof.md](docs/flow-motion-proof.md)。离线视频不是浏览器实机画面或帧率证明。

演出曲目按 **POPSTARS → FANTASTIC → UptownFunk → KILLLOVE → POPSTARS** 循环。前两首分别约59.35/58.99秒、各112音符；用户指定保留完整上传音频的 UptownFunk 为80.01秒/152音符（第3位），KILLLOVE为74.77秒/151音符（第4位）。谱面按实测节拍与瞬态编排，曲名只取附件文件名、不推断艺人。原始上传不放入站点；详见 `docs/GAMEPLAY_AUDIO.md`。准备页沿用 Tech House Groove，见 `docs/LOBBY_AUDIO.md`。旧原创 STAGE RUSH 保留但不作为默认演出音乐。

## 实现边界

- 角色为真实带骨骼 GLB 与三段 Tripo 舞蹈片段，不是静态图片替代。
- 单一主角常驻，换装按需加载。桌面默认头部/身体各 2K 贴图；粗指针/已知低内存设备使用 1K 版。
- 当前人物脸部相似度未通过用户验收，直接原照片重建救援进行中；不得将服装完成等同于本人还原成功。
- 目前支持的云浏览器无法初始化 WebGL。离线 Blender 渲染、结构验证和 UI 操作已进行，但实际 GPU 帧率、视觉 shader 输出和手机硬件顺滑度未实测。
- 排行榜为模拟值；无账号、多人联网或服务端上传。
- 私人参考照片和 Tripo 凭据不在网页工程/public/dist 内。`scripts/tripo_private.py` 仅离线制作时通过隐藏输入使用凭据，网页不调用 Tripo。

详见 `docs/QA_CHECKLIST.md`。发布权限由主任务管理；本项目不得自行转为公开站点。

面部修复方法与限制见 [FACE_RESCUE.md](docs/FACE_RESCUE.md)。照片直接重建的规范头部复用于各自三套服装；本人相似度仍需用户验收。
