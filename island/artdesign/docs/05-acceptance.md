# 05 · 检查、验收与交付

## 每个阶段的证据

| 门槛 | 必须观察 | 不足以通过的证据 |
|---|---|---|
| 图像确认 | 单体完整、同风格、关键结构、视图一致性与尺寸约定 | 只有漂亮场景图 |
| 几何 | 灰模主/侧/背、连接、薄片、孔洞、正面与接点 | Tripo 任务 success 或带纹理小缩略图 |
| PBR | 基础色、normal、roughness/metallic、UV、换光向 | 存在 PBR 字段或开启 delight |
| 装配 | 竖屏构图、比例、接地、穿模、船舱水面 | 只从一个机位看 |
| 优化 | 相同条件前后截图、几何/像素校验与体积 | 减面/压缩命令 exit 0 |
| 性能 | 明确设备、浏览器、视口、DPR、加载状态、样本长度 | 空水体 FPS 或桌面模拟手机尺寸 |

真实截图不能由图像生成工具代替。截图失败、Shader 编译失败、缺材质、未完成加载要明确记录。至少三轮视觉迭代是新场景默认要求，每轮记录前三个问题、修改、复验；明确用户缩小范围时停止并写“未测/未完成”，不补写通过。

## 自动检查

```sh
python3 tools/verify_handoff.py
python3 -m unittest discover -s tools -p 'test_tripo_pipeline.py'
npm --prefix scene-lab run check
node tools/test_assets.mjs
node tools/test_reflection.mjs
npm --prefix tools/mesh-tools test
work/texture-env/bin/python tools/verify_texture_compression.py
```

依赖安装见 04。package 校验针对原始干净归档；修改后出现 hash 差异是预期，先确认有意改动再更新清单。自动检查不包含美术判断，全部通过也不能直接写“视觉 ready”。

## 浏览器证据

保存移动竖屏全景、植物近景、黄昏，另保存关键资产近景和侧面接点。记录 URL 参数、灯光、DPR、视口、模型版本、时间；前后比较用 `still=1`。最终预览恢复动画。

水面转动检查要同时看主画面与倒影：相机连续运动时每帧更新倒影，不能用静止美图证明转动流畅。测量按钮预热 30 帧后采样 12 秒；保持页前台，别同时做 CPU 密集编码。记录 P95 帧间隔、draw calls、含离屏遍三角面，以及倒影更新和过期帧计数。

加载至少区分冷缓存、热缓存、本机服务和移动网络；本例仅做本机服务，不推断 CDN 下载速度。旋转/缩放、横竖屏、背景恢复、WebGL context loss、真实触屏、iOS/Android、温升按实际设备与范围测试。没有设备就写未测。
