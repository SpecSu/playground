# 小岛美术流程 v0.3 · API 执行与检查工作台

> 此文保留充值暂停时的流程设计与历史状态。随后用户已授权执行，八类资产现已生成；当前结果以 [视觉实施与验收记录](VISUAL-REVIEW-v0.3.md) 为准。

日期：2026-10-23。范围：准备可接续的制作流程。用户充值遇到问题，现阶段主动暂停生成；没有上传素材、没有创建新 Tripo 模型，没有声称模型效果合格。

本版承接 `art/v0.1/docs/WORKFLOW-v0.1.md` 的艺术方向，保留该历史文档。地块输入覆盖为 `art/v0.2/assets/ground/primary.png`。其他主体继续用 v0.1 单体主图。背面图仅辅助人工检查，不自动混合上传。

## 1. 现在能检查什么

- 本机工作台：<http://127.0.0.1:8771/>。可浏览八类准备生成的主资产，查看对应验收条件。
- 模型检查：读取生成流程产出的 GLB，或选择本地内嵌纹理 GLB；在浏览器本地解析，不上传文件。
- 显示方式：灰模、原始 PBR、基础色；中性光、暖阳、黄昏；旋转光向、曝光、正背视角、转台、截图和 12 秒帧率测量。
- 场景预演：独立水体与装配位置线框。有模型后按清单组装。缺失模型不会被旧模型或程序化角色替代。
- 队列工具：离线计划、暂停开关、任务记录、接续轮询、下载与格式检查、依赖真实截图记录的验收门槛。

目前 API 仅曾验证认证和余额；图转 3D、下载与纹理任务尚未真实跑通。不能把离线测试通过等同于服务端端到端成功。

## 2. 恢复后的顺序

1. 用户确认充值问题解决后，再由助手恢复生成开关并重新查询实时余额。不根据历史余额自动推断充值结果，不定时后台扣费。
2. 只生成狗狗和松树的几何版本。保留所有原始输出、任务 ID、输入图哈希与参数；未验收前不生成纹理。
3. 在工作台检查灰模主视角、侧面、背面与转台。优先检查狗狗头颈、五官、四肢和脚底，以及松树厚叶、冠层、树干与根部。每轮列出最大的三个问题。
4. 通过灰模检查后，记录截图路径、GLB 哈希、具体结论。此记录只批准几何，不代表颜色或 PBR 已通过。
5. 基于通过的几何任务生成 PBR 材质，使用主图引导，并开启对应版本的去光照。保留 UV、法线、粗糙度、金属度和基础色，不再次靠删贴图掩盖问题。
6. 比较基础色、灰模和 PBR。转动灯光验证高光和阴影是否随光源变化；检查 UV 拉伸、接缝、贴图阴影与塑料感。保存中性、暖阳、竖屏三类浏览器截图。
7. 两个样板成立后，才依次生成方形地块、花灌木、码头、小船、岩石、鱼。每件仍走“几何 → 截图验收 → 纹理”，不整组一次性赌结果。
8. 用同一方形地块母件组装初始小岛，校准统一尺度、方向、接地和水线。所有角色部件在共同父节点中整体变换，不单独挪头、眼睛或耳朵。
9. 正式视觉场景至少做三轮真实浏览器截图对比，每轮修复最大的三个问题。最终保存竖屏全景、植物近景、黄昏氛围。真实手机性能单独验证。

若一件关键资产经过两轮有明确改进目的的试制，结构或可重新打光能力仍明显不合格，停止无目标重试，转交模型师精修或选择风格统一的成熟资产。水体与光照不能弥补失败的轮廓。

## 4. 运行与接续

以下命令以项目根目录为工作目录。预览不需要 API 密钥。

```sh
python3 tools/tripo_pipeline.py catalog
python3 scene-lab/server.py
```

本机浏览器打开 <http://127.0.0.1:8771/>。服务只绑定本机回环地址，只公开 `scene-lab` 与白名单参考图片，不公开项目根目录、钥匙串或任务记录。

离线准备，以下命令不会联网：

```sh
python3 tools/tripo_pipeline.py pause
python3 tools/tripo_pipeline.py plan --assets dog tree
python3 tools/tripo_pipeline.py generate --kind geometry --assets dog tree
python3 tools/test_tripo_pipeline.py
npm --prefix scene-lab run check
```

`generate` 没有 `--execute` 时只显示计划。当前暂停开关为开，即使误加 `--execute` 也会在联网前退出。

充值解决、用户确认恢复后，由执行者按阶段运行。**这段命令当前没有执行。**

```sh
# 历史命令已移除：通过本机凭据管理器注入 TRIPO_API_KEY，见当前 docs/02-tripo-generation.md
python3 tools/tripo_pipeline.py balance
python3 tools/tripo_pipeline.py resume
python3 tools/tripo_pipeline.py generate --kind geometry --assets dog tree --execute
```

生成成功后，点工作台“刷新模型”，逐个检查并保存真实截图。截图从浏览器下载后应整理进 `scene-lab/evidence/round-01/`。助手也可以直接保存浏览器整页截图。看图通过后再记录，例如：

```sh
python3 tools/tripo_pipeline.py approve-geometry --asset dog \
  --evidence scene-lab/evidence/round-01/dog-front.png scene-lab/evidence/round-01/dog-back.png \
  --notes "在此填写实际看图结论与剩余问题，不得套用默认通过文字"
```

树同样记录，然后单独生成纹理：

```sh
python3 tools/tripo_pipeline.py generate --kind texture --assets dog tree --execute
```

首批样板的纹理及实际浏览器画面通过后，用 `approve-pilot --evidence <至少三张截图> --notes <实际结论>` 记录。其后才能生成其他资产。检查记录绑定模型哈希，换模型会使旧记录失效；脚本校验文件与记录，不会自动判断截图美术是否合格。

生成命令中断时，保留 `work/tripo`，再次执行同一命令会按已有 task_id 查询。提交返回未知结果时，不会自动再次扣费；先核对服务端任务，再补齐已核实的任务 ID。失败或需要修订时先归档该版本的记录与模型，不删除历史来假装第一次生成。

## 5. 装配与渲染约定

配置在 `assets/layout.json`。1 单位暂定为 1 米，Y 向上，正面目标 +Z；导入时保留原方向，**必须看模型后**填写整体朝向旋转值，不猜测模型正面。

- 新地块宽度暂定 2.55 m，初始场景为同一母件的 2×2 副本；每件是完整的单块方形。地块采用整体等比缩放，不能拉伸成方形来掩盖不规整的建模。拼缝、草裙碰撞和高度仍待真实资产验证。
- 树高 4.0 m、狗狗高 1.2 m、花灌木高 0.75 m。码头长 2.4 m、小船长 2.25 m。均为初始设计值，不是从参考图精确测出的尺寸。
- 角色、树和花丛按模型底面接地；码头当前按顶面接岸；船体水线用可配置比例暂估。码头柱顶可能高于甲板，拿到真实模型后必须修正甲板接口高度，不能盲用包围盒最终交付。
- `asset.js` 保留 GLTFLoader 的颜色空间、PBR 因子、UV 和法线。灰模仅是临时检查材质，切回时恢复原材质。
- `lighting.js` 统一 sRGB 输出、Neutral 色调映射、一盏投影主光、低强度环境补光；没有默认叠加 SSAO、景深或 Bloom。
- `lagoon.js` 是既有实时水体的实验起点：折射、深度吸收、低分辨率反射、浅水焦散。当前岸线掩码只在真实地块接入后出现，依据暂定方形外轮廓，码头桩、岩石及实际细碎岸线需后续校准。空场景没有虚构岛岸浪花。
- 平台支持 DPR 上限和持续低帧率时降分辨率，测量时保持分辨率固定。正式模型接入后再评估纹理尺寸、共享材质、实例化、KTX2 和必要 LOD；当前没有压缩或减面任何未验收资产。
- 未绑定角色/树不做局部强行形变；鱼可先用整体轨迹检查，不将路径平移称为尾鳍动画。

## 6. 目录与交接边界

```text
island/
  art/v0.1/                   原始艺术流程、十类参考图、生成记录
  art/v0.2/                   新的单块方形地块参考
  tools/tripo_pipeline.py     有暂停与验收门槛的 API 客户端
  tools/test_tripo_pipeline.py 离线回归检查
  work/tripo/                非公开任务记录、输入 token、检查记录
  scene-lab/
    index.html               用户可看的资产工作台
    server.py                本机预览服务
    assets/catalog.json      公开精简清单，不包含凭据或下载签名
    assets/layout.json       整体尺度、朝向、接点草案
    assets/models/<资产>/    geometry.glb / texture.glb，当前为空
    src/                     导入、光照、水体、组装与测量模块
    evidence/                浏览器证据，区分准备阶段与正式美术轮次
    docs/                    执行流程、检查表与验证记录
```

私钥始终只从钥匙串加载到进程环境，Bearer 只发送到 Tripo 官方 API。模型下载不携带 API 密钥。浏览器没有上传或生成 API 入口。不要把任务记录、`tripo-env.sh`、配置或环境变量打包成公开素材。

## 7. 正式验收证据表

复制 `REVIEW-TEMPLATE.md` 建立各资产检查记录。至少保存：输入图与版本、GLB 哈希、几何与材质通道、灰模三视角、中性光换光向、暖阳和竖屏、问题前三名、修改与复验结果。

性能报告写明浏览器、设备、视口、DPR、模型集合、加载时间和缓存状态、P95 帧间隔、上下文丢失。空水体的帧率不可推广到完整场景，桌面窄视口不可推广到真实手机。
